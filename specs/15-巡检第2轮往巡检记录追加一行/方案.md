# 方案：巡检第 2 轮往巡检记录追加一行（#15）

## 现状

- 规划时（基于 origin/main `0668967`）仓根**没有** `巡检记录.md`（第 1 轮的记录没落到主线上，或从未建过）。
- `node --test` 跑的是 `log.test.mjs`（测 `log.mjs` 的 `appendLine`），当前全过；跟 `巡检记录.md` 无关。
- `.gitattributes` 是 `* text=auto eol=lf`，文件按 LF 行尾存。

## 怎么做

1. 写码时先看 `巡检记录.md` 在不在（以当时的工作树为准，主线可能已被别的单改过）：
   - **不在**：新建，内容恰好三行：
     ```
     # 巡检记录

     - 第 2 轮 2026-09-27T13:48:36Z
     ```
     行尾 LF，文件以一个换行结尾（和仓里其它文本文件一致）。
   - **在**：原有内容一字不动；若原文件末尾没有换行，先补一个换行，再追加 `- 第 2 轮 2026-09-27T13:48:36Z` 加换行。
2. 不改 `log.mjs`、`log.test.mjs`、README 或其它任何文件；不借用 `appendLine`（它会 trim，没必要，手写即可）。

## 改哪些文件

- `巡检记录.md`（新建或追加）
- `specs/15-巡检第2轮往巡检记录追加一行/`（需求、方案、之后的结果文档）

## 怎么验证

- `tail -n 1 巡检记录.md` 输出恰为 `- 第 2 轮 2026-09-27T13:48:36Z`（半角字符、"第"与"2"、"2"与"轮"、"轮"与时间之间各一个空格）。
- 新建的情况下 `cat -A 巡检记录.md` 应为 `# 巡检记录$` / `$` / `- 第 2 轮 2026-09-27T13:48:36Z$`，无 `^M`、无尾随空格。
- `git diff --name-only origin/main...HEAD` 只列出 `巡检记录.md` 和 `specs/15-…/` 下的文件。
- `node --test` 通过。

## 风险

几乎没有。唯一要留神的是"一字不差"：空格、冒号、`Z` 大小写，以及不带多余空行。
